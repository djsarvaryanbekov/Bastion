# Localization

Bastion ships in 16 languages: English plus the 15 Steam languages used by Blind Shaman (French, Italian, German, Spanish – Spain, Spanish – Latin America, Simplified Chinese, Traditional Chinese, Japanese, Korean, Polish, Portuguese – Brazil, Russian, Thai, Turkish) and Uzbek (Latin script).

## How it works

- `i18n.js` loads first. It picks the language (saved choice in `localStorage["bastion-language"]`, else the browser/system language, else English) and sets `<html lang>` so CJK and Thai glyphs use the right system fonts.
- English source text is the key. `tr("Start run")` returns the translation, or the English text if there is none.
- Changing the language in Settings reloads the page, so text may be translated once when it is defined.
- Static text in `index.html` is translated in place at startup by `BastionI18n.translateTree`. Everything built in JavaScript must call `tr()` itself.

## Rules for code

1. Wrap every player-visible English literal in `tr("...")`, including data definitions (module names, summaries, descriptions, upgrade names, objectives, toasts, aria-labels, titles).
2. Use one complete sentence per call, never fragments glued together. Put dynamic values in named placeholders:
   `tr("Need {count} more Fragments", { count: missing })`, not `"Need " + missing + " more Fragments"`.
3. Keep the English output byte-for-byte identical to the original (spacing, punctuation, letter case). Automated checks compare English text.
4. Use only plain string literals inside `tr(` so `tools/extract-i18n.cjs` can find them. No template literals, no variables as the first argument, except `tr(def.name)`-style calls on values that were themselves defined with `tr("...")`.
5. Do not translate save keys, IDs, CSS classes, telemetry field names, console/debug output or the `Bastion` name.
6. HTML markup stays outside the key: `'<strong>' + tr("Installed") + '</strong>'`.
7. Node checks load modules without `i18n.js`, so every file that calls `tr` declares this inside its own module scope (IIFE/function), not globally:
   ```js
   var tr = (typeof window !== "undefined" && window.tr) || function (text, vars) { return vars ? text.replace(/\{(\w+)\}/g, function (match, name) { return name in vars ? String(vars[name]) : match; }) : text; };
   ```

## Workflow

```sh
node tools/extract-i18n.cjs   # rebuilds locales/en.json and lists missing strings per locale
node tools/build-locales.cjs  # packs locales/<code>.json into locales.js
npm run build:playtest        # inlines locales.js and i18n.js into the release HTML
```

Translations live in `locales/<code>.json` as `{ "English": "Translation" }`. Placeholders such as `{count}` must stay unchanged. Translations are machine-drafted; each language needs a native-speaker review before Steam release.
