# Drift Bastion — правила работы с главной версией

## Главный файл

Главная актуальная версия игры:

`C:/Users/User/Documents/ChatGPT/Incremental/outputs/Drift_Bastion_Playtest.html`

Когда пользователь просит изменить игру, результат должен попадать именно в этот файл. Сохраняйте его имя и путь. Не подменяйте его старым прототипом, файлом из Downloads, архивом или экспериментальной версией. Само расположение в `outputs` не делает этот HTML одноразовым артефактом.

Перед работой прочитайте текущий главный HTML. Модульные JS/CSS и `index.html` служат рабочими исходниками для его сопровождения. Если они расходятся с главным HTML, сначала сохраните актуальные изменения из HTML и согласуйте с ними исходники; не перезаписывайте главную версию устаревшей сборкой.

## Эксперименты и проверки

1. Перед изменениями сохраните копию текущего главного HTML в отдельном каталоге задачи.
2. Эксперименты проводите на копии по пути `outputs/experiments/<дата-время>-<название>/Drift_Bastion_Playtest.html`. При необходимости копируйте туда и рабочие исходники. Главная версия остаётся доступной во время эксперимента.
3. При делегировании явно сообщайте агенту путь главного HTML и путь его экспериментальной копии. Параллельные агенты не должны одновременно перезаписывать главный HTML.
4. `npm run build:playtest` и `tools/build-standalone.js` сейчас записывают прямо в главный файл. Не используйте их в основном каталоге для пробной сборки; для эксперимента требуется изолированная копия проекта или вывод в отдельный файл.
5. Проверенную правку, которую запросил пользователь, перенесите в рабочие исходники и главный HTML. Если задача была только экспериментом или исследованием, оставьте результат отдельно. Дополнительное подтверждение для уже запрошенной обычной правки не требуется.
6. Проверьте итоговый главный HTML, а не только рабочие исходники. При выпуске пакета обновите `outputs/Drift_Bastion_Playtest_Package.zip` из того же HTML и актуального README. Различайте автоматические проверки и фактический плейтест.

## Сохранность игры

- Сохраняйте совместимость покупок, валюты, постоянных рангов и настроек. Эксперименты и автоматические тесты используют отдельное хранилище, а не профиль пользователя.
- Matter оплачивает копии деталей и улучшения текущего забега; Fragments — постоянные покупки Hangar. Это разные экономики.
- Не обновляйте открытую игру пользователя автоматически: у него может идти незавершённый забег.
- Сохраняйте модульные исходники; статус главного HTML не требует превращать дальнейшую разработку в несогласованные правки одного большого файла.
